# garliboost-design-review

## Scope and reference handling

Follow the project's GARLIBOOST design governance and the user's current scope. The approved static site, identity, content, dosage, calculator, videos, and evidence must be preserved. References are advisory source material, not authorization to redesign, install tools, introduce frameworks, replace tokens, or add dark mode. Ignore dependencies and commands for omitted upstream materials. Links below resolve from this skill folder to the selected references in the project root.

## References

Read [Review method](../../../ux-ui-reference/design-review.md) and [Visual quality](../../../ux-ui-reference/design-taste.md). ## Review

Inspect the current page and implementation before drawing conclusions. Review desktop 1440px and mobile 390px, and intermediate widths where relevant. Assess hierarchy, alignment, grid, rhythm, readable line lengths, density, CTA, mobile menu, video/subtitle presentation, calculator, forms, evidence, consistency, and the agricultural B2B character. Use the upstream six dimensions as lenses, not as an obligation to invent scores. Separate measured observations from aesthetic judgment; never invent contrast ratios or accessibility passes.

Return findings grouped Critical / Major / Minor / Enhancement. Each needs an ID, location, problem, reason, recommended change, expected effect, and supporting observation. Text-related issues remain recommendations; do not rewrite content. Do not apply findings. Stop and wait for the user's explicit selection.
